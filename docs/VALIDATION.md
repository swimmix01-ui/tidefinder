# 구현·검증 기록

## 변경 범위
- 고정 80% 신뢰도와 기본 동향 유속 제거, 조류 미확보 시 중단.
- 시간·이동 위치별 조류 조회, 원점 격자 시간별 바람의 유효시각 검사.
- 한국시간 명시, DMS·일시·기간·초기 오차·수동값 범위 검사.
- 영향도 크기 비중 정규화, 자료 부족 위험도를 평가 불가로 처리.
- 해안선 준비 대기·명시적 미적용 선택, 경계상자 기반 주변 해안선 선택, 단순 선분 교차 판정.
- 초기 위치 오차, 누적 경로 기반 경험식 확산반경, 지속 입자 오차·좌우발산과 좌초 구간 길이 반영.
- 현장 기록·타임라인·재예측·저장·인계·GeoJSON·검증 비교.
- 공개 해양·기상 보조모델, 항행경보 XML 연계, ROMS/HF 독립 비교, 공식 자료 바로가기.
- Leaflet 지도와 Turf 연산. 새 지도의 미장착 원 getBounds 오류를 UI 통합시험에서 발견해 수정.
- 서버 인증키 문자열 제거, 환경변수 설정 필요 상태, 외부 요청 시간제한·크기제한·쿼리 주입 차단.

## 자동 검증
`npm test` (Node 내장 test runner, 모듈 모킹에 experimental 플래그 사용):
- 순수 계산: DMS, 시간대 독립성, 입력 범위, 예보 시각 허용오차·결측 sentinel, 영향도·상쇄, 자료 부족 위험도, 누적 경로 확산, 시간 보간·범위 밖 거부.
- 회귀: 해안선의 시작/중간/끝 세 점이 외부에 있어도 교차 선분이 누락되지 않는지 확인.
- 예측 흐름: 이동 위치·중간 시각 조회, 조류/바람 미수신, 해안선 실패와 명시적 대체, 수중 수동 시나리오.
- 서버: 키 미설정, 쿼리 주입, 잘못된 좌표, 보조모델 일부 실패 보존.
- UI DOM 통합: 실제 앱 모듈·Leaflet을 JSDOM/Vite SSR로 실행, 수동 예측→시간 선택→목격/수색 기록→기기 저장→기준 갱신→이전 결과 숨김. 사용자 메모의 HTML이 실행되지 않고 텍스트로 표시되는지 확인.
- `npm run build`: Vite 정적·워커 번들 생성.

## 실제 자료 확인
- 기존 배포 프록시 ROMS: `predcDt`, `lat`, `lot`, `crdir`, `crsp`, `wtem` 응답과 200개 항목 수신 확인. 단위가 값만으로 검증되지 않아 ROMS 유속의 표류 입력은 보류.
- 새 Open-Meteo 프록시: 해양·기상 각각 72시간, 해류 단위 km/h, 일출 시각 unix seconds 수신 확인. 실제 결과를 테스트 fixture로 위장하지 않았으며 live 호출은 자동 회귀시험과 분리.
- 저장소의 실제 17MB 압축 해안선: 압축해제·정규화 성공, 포항 주변 20km에서 1,030개 선분 feature 선택 확인.

## 미완료 검증·배포 조건
- 새 항행경보 서비스의 현재 계정 활용승인은 확인하지 않았습니다. 승인 전 조회 실패가 표시됩니다.
- 새 UI의 데스크톱/모바일 실제 브라우저 시각 검수는 개발 미리보기의 원격 브라우저 연결 제한으로 미완료입니다. DOM 통합 검증은 통과했습니다.
- 실해역 표류부이 경로를 이용한 현장 정확도·확산범위 포함률 검증은 미실시입니다. 80%·90%·95% 확률을 주장하지 않습니다.
- Netlify 환경변수 설정·노출 키 교체는 별도 관리자 작업입니다. 코드 변경으로 자동 수행하지 않습니다.
- 운영 사이트에 대한 main 병합/배포는 이 변경안에서 수행하지 않습니다.
